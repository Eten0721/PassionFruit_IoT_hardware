# 硬體接線與驗收摘要

本文件集中硬體接線安全、上電檢查與實機驗收。GPIO、角度、分類 code、距離與 timing 以 [`docs/CAPTURE_SPEC.md`](../docs/CAPTURE_SPEC.md) 為唯一來源；平台尺寸與機構決策見 [ADR-0016](../docs/adr/0016-hardware-platform-feeder-sorter-redesign.md)，演進歷史由 Git 保存。

## 供電與共地

- ESP32、HC-SR04、三站與分類器共四顆 MG996R、XINHUI `60KG` 送料馬達及兩組 DC 電源負極必須共地。
- 伺服不得由 ESP32 的 `3.3 V`、`5 V` 或 `VIN` 腳供電。
- 上電時觀察電壓降、線材溫升、伺服異音與 ESP32 是否重新啟動。

### 兩組獨立 12 V／20 A 電源

全部馬達取消電池盒，改用兩組彼此獨立的 `AC 110 V → DC 12 V／20 A` 開放式電源與兩顆 LM25116 降壓模組。兩組電源均尚未通過負載、壓降與溫升驗收：

```text
AC 110 V ── 電源 A 12 V／20 A ── LM25116 A ── 6.0 V ──┬── Gate 1 MG996R
                                                        ├── Gate 2 MG996R
                                                        ├── Gate 3 MG996R
                                                        └── 分類器 MG996R

AC 110 V ── 電源 B 12 V／20 A ── LM25116 B ── 8.4 V ───── XINHUI 60KG

電源 A DC 負極 ──┐
電源 B DC 負極 ──┼── ESP32 GND 與全部伺服 GND
ESP32 GND ───────┘

ESP32 各訊號 GPIO（依資料採集規格）── 各伺服訊號線
```

- 電源 A 與 B 的 DC 正極不得互接、串接或並接；ESP32 使用自己的電源，只共用 DC 負極／GND。
- LM25116 A 必須先在未接伺服時調到 `6.0 V`，接上四顆 MG996R 後仍不得超過 Tower Pro [MG996R](https://towerpro.com.tw/product/mg996R/) 的 `6.6 V` 額定上限。
- LM25116 B 必須先在未接馬達時調到 `8.4 V`；XINHUI 到貨後先核對連續旋轉版本、銘牌與極性，再接上負載。
- 四顆 MG996R 以保守配電值 `2.5 A／顆` 計算為 `10 A／60 W`；XINHUI 依購買頁 `8.4 V／6.2 A` 計算為 `52.08 W`。兩條不同電壓電源軌的電流不得直接相加，伺服端估算功率可合計為 `112.08 W`。
- 單顆 `12 V／20 A` 電源的電壓電流乘積為 `240 W`；賣場 `250 W` 及 LM25116 模組 `20 A／300 W` 都只視為商品標示。LM25116 是降壓控制器，實際模組能力取決於 MOSFET、電感、電容、PCB、散熱與環境溫度。
- 已購買的 `20 AWG` 線材不得直接作為共用 `20 A` 主幹能力證明。線材是否可用須依實際長度、每一分支電流、絕緣耐溫、壓降、端子額定與連續運轉溫升判定；大電流不得通過麵包板電源軌。
- 每條伺服分支與共用主幹須配置符合實測負載與線材能力的保護，不得只依電源供應器最大額定值選保險絲。

### AC 市電安全

- 兩顆開放式電源的金屬外殼必須接保護接地；市電 Line、Neutral 與 Protective Earth 必須依電源端子標示接線，不得用 DC GND 取代保護接地。
- Line 端須有適當保險絲與可辨識的總斷電裝置，市電端子須加不可徒手碰觸的遮罩，線材須有拉力固定與絕緣保護。
- 配線、鎖端子、調整 LM25116 或移動金屬平台前，必須切斷兩組市電輸入並確認 DC 輸出已降至安全電壓。
- 市電配線應由具備相應能力的人員完成。任何裸露導體、保護接地不明或外殼帶電情況都禁止上電。

## HC-SR04 Echo 電壓安全

HC-SR04 使用 `5 V` 供電時，Echo 會輸出接近 `5 V` 的脈波。ESP32 GPIO 不耐受 `5 V`，Echo 必須先經分壓或邏輯電平轉換。

建議分壓：

```text
HC-SR04 Echo --- R1 2.2 kΩ ---+--- ESP32 Echo input
                              |
                            R2 3.3 kΩ
                              |
GND --------------------------+--- ESP32 GND
```

以 `5.0 V` Echo 計算，輸入端約為 `3.0 V`。`R1` 是 Echo 到輸入端的上方電阻，`R2` 是輸入端到 GND 的下方電阻；兩者裝反會造成過壓。

正常目標為 ≤ `3.3 V`，絕不可超過 `3.6 V`，以萬用表或示波器實測為準。禁止用單一串聯電阻取代分壓。

## 伺服接線與機械檢查

- 訊號線依資料採集規格接線，不因新增裝置任意交換。
- 上電前手動檢查三站 MG996R 閘門與下置式分類器的完整行程，確認不碰硬限位、軌道、落料管或相鄰連桿。
- L 型閘門以後方桿件持續接觸並推動果實；安裝高度須能可靠攔截與推動，避免從果實上方掠過或刮到底板。
- 舊平台曾以墊高中間馬達約一個桿件厚度避開相鄰 L 型桿碰撞；重製平台或拆裝後須重新檢查完整旋轉路徑與固定件。
- HC-SR04 原型曾由軌道右側移至左側避開閘門；移位後須重新檢查感測方向、固定件反射與觸發穩定性。
- 三站閘門與分類器必須能安全歸位；Gate 3 關閉時必須能可靠攔住完成第 3 張拍攝的果實。
- 位置型 MG996R 沒有位置回授；`classification_sorter_completed` 只表示分類器轉向後等待 `500 ms`、Gate 3 放行、`1000 ms` 落果保持、三顆 Gate 與分類器同時歸位及共同等待 `500 ms` 的控制時序完成。
- XINHUI 連續旋轉伺服沒有位置回授；`feed_cycle_completed` 只表示送料已由 HC-SR04 正常停止並完成回報。Dashboard「暫停」是優雅暫停，不是實體緊急斷電。
- 一體式送料筒頂部保持開放。Dashboard「優雅暫停」只禁止後續送料，不中止目前 `feed_one`。正常清料必須等待 HC-SR04 或最大運轉時間使 ESP32 回報送料已停止，並目視確認分槽盤完全靜止後才能伸手。切斷送料專用電源 B 只保留給緊急狀況；重新送電前必須依資料採集規格完成 terminal report 或 ESP32 重新啟動復原，且手已離開送料筒。恢復供電後必須先執行一次測試送料。
- 刪除未分類果實不會自動開啟 Gate 3。操作員必須切斷伺服電源、確認分類器與閘門不會動作，再人工移除果實。

## 上電前檢查

1. 切斷兩組 AC 輸入與全部 DC 輸出，檢查保護接地、市電端子遮罩、保險絲、線材固定、電源極性、裸線、平台金屬件可能接觸處、分壓電阻位置、訊號線與所有 GND。
2. 確認電源 A、B 的 DC 正極完全隔離，並排除伺服外部電源經 ESP32 或 USB 回灌至電腦的路徑。
3. 不接任何伺服，分別上電量測 LM25116 A 為 `6.0 V`、LM25116 B 為 `8.4 V`；確認極性與輸出穩定後再次完全斷電。
4. 只接新 ESP32 與 USB，確認可正常燒錄與啟動；再接 HC-SR04 並量測 Echo 輸入峰值。
5. 先接電源 A 與四顆 MG996R，空載執行歸位及逐顆完整行程；斷電後再接電源 B 與 XINHUI，確認停止脈波沒有爬行。每一步都量測電壓並檢查異常溫升。
6. 以 Serial log 確認裝置成功初始化，且沒有重複 attach 或 reset。

任何電擊感、電腦黑屏、異常溫升或 ESP32 reset 都立即切斷兩組 AC 輸入並停止驗收。

## 實機驗收

1. 依資料採集規格完成空軌感測、三站停止拍攝與首張延遲驗收。
2. 確認不同尺寸、形狀與蒂頭方向的果實能以直接 Home／Release 控制依序攔截與放行，三顆 MG996R 不會夾果、過度推擠或造成相鄰桿件干涉；慢速角度遞增只依 Issue [#16](https://github.com/Eten0721/PassionFruit_IoT_hardware/issues/16) 的失敗證據決定。
3. 依規格逐一驗證四個分類出口、歷史 alias、未知 code、Gate 3 與分類器安全歸位。
4. 第 3 張照片保存後確認 Gate 1／2 維持 Release、Gate 3 維持 Home；依資料採集規格逐一驗證四個分類角度，並以高速錄影確認分類器轉向後等待 `500 ms` 才開啟 Gate 3、Gate 3 開啟後保持目標角度至少 `1000 ms`，最後四顆馬達同時歸位並等待 `500 ms`。
5. 重送相同 `command_id`，確認分類器、Gate 3 與送料動作都不重複。
6. 動作期間中斷網路，恢復後只重送 report；斷電或重新啟動後不得自動放行 Gate 3。
7. 確認分類器未就位、無效分類、timeout 或歸位失敗時 Gate 3 保持關閉，且自動送料停止。
8. 空送料筒校正 XINHUI 停止脈波，確認沒有爬行；再以 `10` 顆執行目前階段的機構驗證，自行調整能可靠帶動分槽盤且不造成雙送的最慢驅動脈波，以及 `1000～20000 ms` 範圍內的最大運轉時間。
9. 現階段使用同一批 `10` 顆、不補回已送出的果實，連續驗證剩餘量由 `10` 顆降至 `1` 顆；正式階段仍需以混合尺寸、形狀與蒂頭方向連續完成 `20` 顆單顆送料與完整分類。每次 `feed_one` 都要恰好一顆、無漏送／雙送、馬達確實停止，且無須人工重對分槽盤。
10. 送料至少連續執行 `10` 次，逐次記錄 `8.4 V` 電源軌的最低電壓、峰值電流與未起轉次數；同一段 `20` 顆完整流程另確認 XINHUI 與四顆 MG996R 無抖動／異音、ESP32 無 reset，兩條電源軌保持在所接馬達的額定範圍，且電源、LM25116、開關、配電端子及線材無異常溫升。任一項失敗，修正後重新累計。
11. 操作員記錄實體觀察與量測結果；軟體測試與 log 只能輔助判讀，不得代替實體驗收。
