# HC-SR04 與 ESP32 的 `3.3 V` Echo 安全檢查

## 必要接線

HC-SR04 使用 `5 V` 供電時，Echo 腳會輸出接近 `5 V` 的脈波。ESP32 GPIO 不耐受 `5 V`，因此 Echo 不可直接接到 GPIO `27`。

建議使用電阻分壓：

```text
HC-SR04 Echo --- R1 2.2 kΩ ---+--- ESP32 GPIO 27
                              |
                            R2 3.3 kΩ
                              |
GND --------------------------+--- ESP32 GND
```

以 `5.0 V` Echo 計算，GPIO 端約為 `5.0 × 3.3 / (2.2 + 3.3) = 3.0 V`。`R1` 是 Echo 到 GPIO 的上方電阻，`R2` 是 GPIO 到 GND 的下方電阻；兩個裝反會使 GPIO 電壓過高。正常目標為 ≤ `3.3 V`，絕不可超過 `3.6 V`，實際量測值優先。

## 其他接線條件

- HC-SR04 的 VCC 可維持接 `5 V`；ESP32 的 `3.3 V` Trigger 通常可作為 HC-SR04 的有效 Trigger，若模組讀值不穩再以示波器或替代電平轉換器確認。
- HC-SR04、ESP32 與伺服馬達外接電源必須共地。
- SG90／其他伺服不可由 ESP32 的 `3.3 V` 腳供電；伺服電源波動會影響 HC-SR04 與 Wi-Fi 穩定性。
- 禁止用單一串聯電阻取代分壓，也禁止將 Echo 直接接到 ESP32 GPIO。

## 刷入新版 firmware 前檢查

1. 斷電後檢查 `R1`、`R2` 接線方向與所有 GND 是否共地。
2. 只啟動 HC-SR04 與 ESP32，讓 Echo 持續量測；以萬用表或示波器確認 GPIO `27` 端正常峰值 ≤ `3.3 V`，絕不可超過 `3.6 V`。
3. 接回伺服電源後，再量一次以確認沒有共地鬆脫或雜訊造成過壓。
4. 使用 Serial Monitor 進行至少 `100` 次空軌量測，確認 `kEchoPulseTimeoutUS = 12000UL` 時 Echo 等待上限為 `12 ms`，完整 `sensor_read_us` 未跨過約 `12.1 ms` warning 門檻。
5. 最後以實際百香果確認觸發距離 `6.0 cm` 與重新待命距離 `8.0 cm`；調整距離或閘門位置前，先保留目前量測記錄。

此檢查是硬體安全前置條件；軟體的 timeout、retry 與首站捷徑均不能補償 `5 V` GPIO 過壓。
