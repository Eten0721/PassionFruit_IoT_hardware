# MG996R 分類器接線與驗收

## 接線

- MG996R 訊號線固定接 ESP32 GPIO `25`。
- MG996R 必須使用獨立外部伺服電源，不可由 ESP32 的 `3.3 V` 或 `5 V` 腳供電。
- 外部電源 GND、ESP32 GND、三顆 SG90 電源 GND 必須共地。
- 三顆 SG90 維持 GPIO `18`、`19`、`21`；不得因新增 MG996R 更換既有腳位。

## 角度與時間

- Home：`85°`
- 上等：`25°`（code：`high`）
- 中等：`55°`（code：`medium`）
- 下等：`115°`（code：`low`）
- 加工：`145°`（code：`processing`）
- 分類位置保持：`1000 ms`
- Home 穩定：`500 ms`
- Firmware 動作 timeout：`5000 ms`

## 上電前檢查

1. 不接果實，確認外部電源極性與共地。
2. 確認 MG996R 機構在 `25°` 到 `145°` 間不會撞到硬限位。
3. 先刷入支援 `classify_fruit` 的正式 firmware，再啟動新版 Django。
4. 上電後確認三顆 SG90 歸位，MG996R 同時回到 `85°`，ESP32 未因瞬間電流重新啟動。

## 實機驗收

1. 依序送出 `high`、`medium`、`low`、`processing`，確認分別前往上等 `25°`、中等 `55°`、下等 `115°`、加工 `145°`。
2. 以舊版 Django 相容測試送出 `high_medium` 與 `discard`，確認仍分別前往上等 `25°` 與中等 `55°`；舊 alias 不得恢復舊角度。
3. 送出未知 code，確認不前往任何分類角度、嘗試回到 `85°`，並回報 `invalid_classification_code`。
4. 重送相同 `command_id`，確認 MG996R 不重複動作。
5. 動作期間中斷網路，恢復後確認只重送 report，不重新分類。
6. 以 Serial log 確認 GPIO `18／19／21／25` 均成功 attach。
7. 以高速錄影確認第三站仍先完成 Gate 3 放行、三閘門歸位與 `capture_sequence_finished`，人工分類後才動作 MG996R。

完成只代表控制流程完成；目前沒有位置回授，不可宣稱機械已被感測器確認到位。

新版 Django 只送出 `high`、`medium`、`low`、`processing`。`high_medium` 與 `discard` 僅是新版 firmware 為舊 Django 保留的輸入 alias；跳過／刪除暫存資料的 `/api/discard/` 與分類 alias 無關。現場不再設置廢棄級距，原本應判為廢棄的果實後續歸入加工。
