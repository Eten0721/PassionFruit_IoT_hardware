## 目前狀態

已決定資料採集流程改為「Django 中央狀態機協調手機與 ESP32，完成三段 SG90 閘門停止拍攝 3 張」。舊版「滾動中連拍 6 張」只保留為歷史背景，不再作為主要開發方向。

目前也已確認：手動拍攝不能是純 Django 與手機相機流程。因為實體拍攝軌道上有三段 SG90 閘門，手動拍攝只取代 HC-SR04 的開始訊號，後續仍必須由 ESP32 控制閘門攔截與放行。

最新需求已從「固定延遲三站流程」修正為「每站照片上傳完成後才放行下一站」。手機是否完成拍攝以 Django 收到並保存當站照片為準，不再使用固定延遲猜測。

## 已確定方向

- 每顆百香果會在三個拍攝站點各停止一次。
- 三個站點各拍攝 1 張照片，預設共 3 張。
- 自動模式由 HC-SR04 觸發 ESP32，ESP32 回報 Django 開始拍攝工作階段。
- 手動模式由 dashboard 建立開始請求，ESP32 輪詢 Django 後開始同一套三站流程。
- Django 是流程狀態中心。
- 手機輪詢 Django 取得拍攝請求，每站只拍攝並上傳 1 張照片。
- ESP32 輪詢 Django 取得馬達命令，並回報站點就緒與流程完成。
- SG90 閘門以 `45` 度作為攔截預設角度，以 `0` 度作為放行角度。
- `servo_settle_ms` 與 `fruit_settle_ms` 只用於機械穩定與果實停穩，初始可調範圍建議 `100` 到 `300` ms。
- 照片先暫存在 `dataset/temp/fruit_XXX/`。
- 使用者確認照片後，再將整個 `fruit_XXX/` 分類到 `上中等`、`下等`、`加工`、`廢棄` 其中一個資料夾。
- 每次成功分類後，必須寫入 `metadata.csv`。
