## 技術決策紀錄

## 2026-07-06：資料採集流程改為三段 SG90 閘門停止拍攝

### 決策

資料採集流程由「滾動中連拍 6 張」改為「ESP32 三段 SG90 閘門停止拍攝 3 張」。

新的標準流程是：

1. HC-SR04 偵測百香果進入拍攝軌道，或使用者在 dashboard 按下手動拍攝。
2. ESP32 開始三段 SG90 閘門流程。
3. ESP32 回報 Django 第 1 站就緒後，Django 通知手機拍攝並等待 `img_01.jpg` 上傳完成。
4. Django 保存 `img_01.jpg` 後，ESP32 輪詢取得 `release_gate_1` 並放行第 1 閘門。
5. 第 2、3 站重複相同握手，直到 `img_03.jpg` 上傳完成。
6. 第三段閘門轉到 `0` 度放行，百香果離開拍攝區。

### 原因

- 百香果滾動時連拍容易產生動態模糊。
- 三段閘門能讓百香果在拍攝時保持靜止，提高照片清晰度。
- 每張照片對應固定站點，後續資料管理、人工確認與 AI 分析都比較穩定。

### 影響

- Django 拍照流程需由六連拍改為三張站點式拍攝。
- `dataset/temp/fruit_XXX/` 每個樣本預設保存 `img_01.jpg`、`img_02.jpg`、`img_03.jpg`。
- `metadata.csv` 需記錄 `capture_count` 與三個站點拍攝狀態。
- ESP32 需新增三段 SG90 閘門攔截、拍攝觸發與放行流程。
- dashboard 預覽與分類流程需以三張照片為主。

## 2026-07-06：手動拍攝只取代 HC-SR04 開始訊號

### 決策

手動拍攝不再代表純軟體拍攝，也不是只由 Django 與手機相機完成三張照片。使用者在 dashboard 按下「手動拍攝」時，Django 應向 ESP32 發出開始流程請求；後續仍由 ESP32 控制三段 SG90 閘門攔截、等待拍攝與放行。

自動模式與手動模式的差異只有開始訊號來源：

- 自動模式：HC-SR04 偵測百香果後，由 ESP32 開始流程。
- 手動模式：dashboard 按鈕觸發 Django，再由 Django 要求 ESP32 開始流程。

### 原因

- 實體軌道上已有 SG90 閘門，若沒有 ESP32 控制放行，百香果會卡在閘門前。
- 手動模式若繞過 ESP32，會與真實硬體狀態不一致，測試結果不能代表正式流程。
- 讓手動與自動共用後續流程，可降低 Django、手機相機與 ESP32 狀態不同步的風險。

### 影響

- Django、ESP32、手機相機必須一起設計流程狀態與錯誤處理。
- ESP32 不可用時，dashboard 手動拍攝應回報無法開始流程，而不是直接拍照。
- SG90 閘門未回應或手機未完成拍攝時，流程不應繼續放行到下一站。

### 暫緩項目

- AI 推論與自動分類器控制先暫緩。
- 先完成 Django dashboard 手動觸發 ESP32 三站流程、HC-SR04 自動觸發 ESP32 三站流程與資料管理，再接 AI 推論。

## 2026-07-06：改為 Django 中央狀態機與 ESP32 輪詢握手

### 決策

不使用固定延遲猜測手機是否拍攝完成。Django 作為流程狀態中心，手機與 ESP32 都透過輪詢或回報方式同步狀態。

新的握手原則：

- 手機輪詢 Django，取得目前是否有某站 `capture_requested`。
- 手機每次只拍攝並上傳一個拍攝站點的單張照片。
- Django 確認當站照片保存成功後，才設定下一個 `motor_command`。
- ESP32 輪詢 Django，取得 `release_gate_1`、`release_gate_2`、`release_gate_3` 等馬達命令。
- ESP32 回報 `station_1_ready`、`station_2_ready`、`station_3_ready`、`capture_sequence_finished`。

### 原因

- HTTPS 與輪詢架構下，ESP32 作為 client 輪詢 Django 比 Django 主動呼叫 ESP32 更穩定。
- ESP32 不需要架設 HTTPS API server，也不需要處理被電腦端連入的憑證與 IP 問題。
- 手機是否拍攝完成應以 Django 收到並保存照片為準，不能用固定延遲推測。
- 每站照片保存成功後才放行下一站，可降低資料錯位與漏拍風險。

### 影響

- Django 需要新增三站拍攝工作階段狀態機。
- 手機 `/camera/` 需要從一次連拍改為每站單張拍攝與上傳。
- ESP32 需要從單次 trigger 改為輪詢馬達命令並回報站點狀態。
- 延遲只保留給 `servo_settle_ms` 與 `fruit_settle_ms`，初始可調範圍建議 `100` 到 `300` ms。
