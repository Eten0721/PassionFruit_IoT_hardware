# 百香果 IoT 系統部署與操作說明

[回到專案首頁](../README.md)

本文是部署與日常操作的入口。首次部署依第 1～5 節完成；環境與韌體已備妥時，直接看「[日常啟動](#6-日常啟動與更換網路)」。硬體參數、配網安全條件與控制協定以 [CAPTURE_SPEC.md](CAPTURE_SPEC.md) 為準，實作與實機驗收狀態見 [CURRENT_STATUS.md](CURRENT_STATUS.md)。

## 1. 準備電腦與區域網路

- Windows 電腦：安裝 Git、Git LFS、Anaconda 或 Miniconda；首次下載專案與套件需要網際網路。
- 電腦、ESP32 與相機手機最後須加入可彼此連線的同一區域網路；ESP32 使用 `2.4 GHz` Wi-Fi，不使用隔離裝置的訪客網路。
- 電腦保留自動取得 IP 與 DNS。部署完成後可驗證沒有網際網路的區網操作，但須保留 Wi-Fi 與裝置互通。
- 初次燒錄先只接 ESP32 與可傳資料的 USB 線。接回馬達前依 [上電前檢查](../record_image/硬體接線與驗收摘要.md#上電前檢查) 完成斷電檢查。

### 先分清楚三種網址

| 用途 | 網址 | 開啟條件 |
|---|---|---|
| ESP32 的 Wi-Fi 設定頁 | `http://192.168.4.1/` | 手機或電腦已連上 `PF-Setup-xxxxxx` 熱點 |
| 電腦本機 Dashboard | `https://127.0.0.1:8000/dashboard/` | 在執行 Django 的同一台電腦開啟 |
| 手機相機頁 | Dashboard 當次顯示的 HTTPS 相機 QR／網址 | 手機已切回與 Django 相同的區域網路 |

`192.168.4.1` 是 ESP32 自己建立的設定熱點位址，目前韌體每次開啟設定熱點都使用這個 IP，不會隨機改變。ESP32 加入目標 Wi-Fi 後取得的 IP，以及 Django 電腦的 IP，則由路由器分配，可能改變。設定頁使用 **HTTP**；Dashboard 與手機相機使用 **HTTPS**。手機不能用 `127.0.0.1` 連到電腦。

## 2. 首次建立電腦環境

### 2.1 下載專案

開啟可使用 `conda` 的 PowerShell，執行：

```powershell
git lfs install
git clone https://github.com/Eten0721/PassionFruit_IoT_hardware.git
cd PassionFruit_IoT_hardware
git lfs pull
Get-Item Django_Server/models/ROI.pt,Django_Server/models/Color.pt,Django_Server/models/Wrinkle.pt,Django_Server/models/Defect.pt,Django_Server/models/GradeStage1.json,Django_Server/models/GradeStage2.json
```

已有 checkout 時直接進入該目錄，不要重複 clone。六個模型檔案必須是 Git LFS 下載後的實際檔案，不能只有文字 pointer；正式部署只讀取這些固定檔名。

### 2.2 建立並啟用 PF

先執行 `conda env list`。如果沒有 `PF`，才建立：

```powershell
conda create -n PF python=3.14.4 pip -y
```

每次開啟新的終端機都要啟用環境：

```powershell
conda activate PF
python --version
```

目前專案基準是 Python `3.14.4`。若 `conda` 無法辨識，改用 Anaconda／Miniconda 提供的終端機，不改用系統預設 Python。

### 2.3 安裝 Django 與推論依賴

以下指令都在本 Repository 根目錄、已啟用的 `PF` 環境執行。全新環境先安裝 CUDA `12.8` 版 PyTorch，再安裝 Django 與本機 YOLO 推論所需套件：

```powershell
python -s -m pip install torch==2.11.0 torchvision==0.26.0 --index-url https://download.pytorch.org/whl/cu128
python -s -m pip install -r Django_Server/requirements.txt
python -s -m pip check
```

已有相同版本的 PyTorch 時可略過第一行；有可用的 NVIDIA CUDA GPU 時使用 GPU，否則使用 CPU。`pip check` 應顯示 `No broken requirements found.`。Python `-s` 避免使用者層套件遮蔽 `PF` 內的版本。

Django 的部署推論由本 Repository 維護，不需要 clone 模型 Repository、安裝其依賴或存取外部資料。更新模型直接替換 `Django_Server/models/` 中的固定檔名並重啟 Django，清單見[正式部署模型](../Django_Server/models/README.md)；模型任務與類別須符合 [檢測契約](CAPTURE_SPEC.md#檢測與判級)。缺少或不相容的權重會明確回報檢測失敗。

### 2.4 Demo 設定與資料位置

目前 Demo 不需要 `.env` 或手動設定金鑰，安裝套件後直接依第 3 節啟動 Django。照片與結果存於 `Django_Server/dataset/`，依蒐集與自動檢測分區（分區與舊資料規則見 [資料分區](CAPTURE_SPEC.md#資料分區)）；操作設定與目前模式存於 `Django_Server/runtime_config/`。這些資料由檔案系統保存，不需要執行 database migration。

Django 每次啟動會自動產生隨機 `SECRET_KEY`。目前未使用登入、Django session 或持久化簽章，因此符合單一程序的區網 Demo；將來加入這些功能或使用多程序部署時，須改用各程序共用且能跨重啟保存的私密金鑰。金鑰用途見 [Django 官方說明](https://docs.djangoproject.com/en/5.2/ref/settings/#secret-key)。

## 3. 啟動 Django 與確認網路

### 3.1 Windows 防火牆

先讓電腦加入本次區網。只在可信任的實驗室網路上，以系統管理員 PowerShell 執行；依 `Get-NetConnectionProfile` 顯示的名稱替換 `Wi-Fi`，有線網路可能為 `Ethernet`：

```powershell
Get-NetConnectionProfile
Set-NetConnectionProfile -InterfaceAlias "Wi-Fi" -NetworkCategory Private
if (-not (Get-NetFirewallRule -Name "PassionFruit-Django-8000" -ErrorAction SilentlyContinue)) {
    New-NetFirewallRule -Name "PassionFruit-Django-8000" -DisplayName "PassionFruit Django HTTPS" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8000 -Profile Private -RemoteAddress LocalSubnet
}
if (-not (Get-NetFirewallRule -Name "PassionFruit-mDNS-5353" -ErrorAction SilentlyContinue)) {
    New-NetFirewallRule -Name "PassionFruit-mDNS-5353" -DisplayName "PassionFruit mDNS" -Direction Inbound -Action Allow -Protocol UDP -LocalPort 5353 -Profile Private -RemoteAddress LocalSubnet
}
```

TCP `8000` 用於 Django HTTPS，UDP `5353` 用於裝置探索。保留 Windows 防火牆；路由器也須允許區網裝置互通。

### 3.2 開啟伺服器

在一般終端機啟用 `PF`，從硬體 Repository 根目錄執行：

```powershell
cd Django_Server
python -s manage.py check
python -s manage.py runsslserver 0.0.0.0:8000 --noreload
```

`check` 無錯誤後再啟動。伺服器執行期間保留此終端機；停止時按 `Ctrl+C`。使用目前專案的 `runsslserver` 提供 HTTPS。

### 3.3 選擇本次網路

1. 在這台電腦的瀏覽器開啟 `https://127.0.0.1:8000/dashboard/`。
2. 展開頂部「確認本次使用的網路」，選擇目前連線的 Wi-Fi／Ethernet，按「確認使用」。即使只有一個候選，每次 Django 啟動仍要確認。
3. 確認頁面顯示「控制端網址」及相機 QR Code。先記下控制端網址，ESP32 自動探索失敗時會用到。

此時 ESP32 或相機尚未加入而顯示未就緒是正常的；繼續下一節。

## 4. ESP32 首次燒錄與 Wi-Fi 設定

### 4.1 首次燒錄

依 [ESP32 燒錄指南](../環境部署/README.md) 安裝開發板與程式庫、設定私密熱點密碼，再上傳正式韌體。已燒錄支援配網的版本時，日常啟動與換網直接做以下操作。

### 4.2 開啟設定熱點

1. ESP32 正常上電，先讓 BOOT 保持放開。不要按住 BOOT 上電或重置來開設定頁。
2. 沒有已保存的 Wi-Fi 設定時，初始化完成後會自動開熱點；已有設定時，等裝置安全閒置，再按一下 BOOT。
3. 用手機的 Wi-Fi 設定連上 `PF-Setup-xxxxxx`，輸入 `setup.local.h` 中設定的熱點密碼。尾碼用來辨識裝置。

BOOT 腳位仍須依實際板型核對。送料、拍攝、分類或安全鎖存在時可能拒絕配網；可查看 Dashboard 底部「ESP32 網路設定」的原因。完整條件見 [配網規格](CAPTURE_SPEC.md#esp32-配網與控制端識別)。

### 4.3 手動開啟並保存設定頁

1. 手機保持連上 ESP32 熱點。若手機提示「沒有網際網路」，選擇繼續使用這個 Wi-Fi。
2. 打開瀏覽器，在**網址列**輸入 `http://192.168.4.1/`。不依賴設定頁自動彈出，也不把網址輸入搜尋框。
3. 按「掃描 SSID」選取目標 Wi-Fi，或直接輸入 SSID；輸入的是**目標 Wi-Fi 密碼**，與前一步的 ESP32 熱點密碼分開。
4. 「手動 Django HTTPS origin」先留空，讓 ESP32 自動探索。需要備援時，填入 Dashboard 顯示的控制端網址，例如 `https://192.168.0.93:8000`；不要附加 `/dashboard/`、`/camera/` 或 API 路徑，也不要照抄範例 IP。
5. 按「連線並保存」。成功時會顯示 `saved` 與取得的 IP，並啟用「退出連線」；設定保存於 ESP32 NVS，重新上電仍保留。
6. 按「退出連線」關閉設定熱點，再手動將手機切回目標 Wi-Fi。手機不一定會自動切回；熱點關閉後原設定頁無法繼續使用是正常的。

密碼錯誤或逾時時，設定熱點會保留，依錯誤訊息修改後重試。保存 Wi-Fi 不需要等 Django 上線，但硬體運作仍須通過 Django 的就緒與安全檢查。

## 5. 手機相機與第一次操作

1. 確認手機已切回與 Django 相同的區網，用 Chrome 開啟 Dashboard 顯示的相機 QR／網址。
2. 按「開啟相機」並允許權限；確認手機顯示即時畫面、Dashboard 顯示相機就緒。使用期間保持相機頁在前景，不鎖定螢幕。
3. 先選「蒐集模式」＋「純拍攝」，按「開始執行」，檢查三張照片都已保存，再完成人工分類。此模式不操作馬達。
4. 要使用硬體時，先完成 [接線與上電檢查](../record_image/硬體接線與驗收摘要.md#上電前檢查)，確認 ESP32 已連線，再依 Dashboard「停穩設定與送料校正」及 [正式開始條件](CAPTURE_SPEC.md#開始條件) 完成校正。只在全部門檻成立後開始硬體流程。

新 IP、電腦或手機可能遇到 HTTPS 憑證警告或相機權限問題。相容性與安全來源判斷以 [手機與離線驗收前提](CAPTURE_SPEC.md#手機與離線驗收前提) 為準；不能把一次成功視為所有裝置都已驗證。

部署完成的判斷是：Dashboard 已確認網路、相機就緒且三張照片實際保存；硬體模式另需 ESP32 正式連線、送料校正與安全條件成立。只看到 Wi-Fi 已取得 IP 還不夠。

## 6. 日常啟動與更換網路

環境與韌體已部署後，不必重裝套件、重建私密設定或重新燒錄：

1. 電腦連上本次區網，啟用 `PF`，依第 3.2 節啟動 Django。
2. 在本機 Dashboard 確認本次網路；ESP32 正常上電後使用已保存的 Wi-Fi。
3. 手機加入同一區網，重新開啟本次相機 QR，啟用相機並確認就緒。
4. 依本次拍攝模式檢查開始條件，再按「開始執行」。

更換 Wi-Fi 時，先讓裝置安全閒置，電腦與手機加入新網路，重新確認 Dashboard 介面，再依第 4.2～4.3 節重設 ESP32。只換電腦或 DHCP IP 時，ESP32 會重新探索，手機重新掃目前 QR；曾填手動 origin 且探索不可用時，須更新備援網址。換網不需要修改 Firmware 的 API URL 或重燒。

若上一輪曾失聯、帶果實重啟或有待處理資料，先依 Dashboard 與 [安全復原規格](CAPTURE_SPEC.md#失聯門檻與安全交握) 清理並完成人工確認；重新連線或配網不會解除安全鎖。

## 7. 常見問題

| 現象 | 直接檢查 |
|---|---|
| 找不到 ESP32 設定熱點 | 核對 `setup.local.h` 的熱點密碼、正常上電後的 BOOT 操作與配網阻擋原因；缺少有效密碼會回 `setup_ap_failed`。 |
| `192.168.4.1` 打不開 | 手機是否仍連著 `PF-Setup-xxxxxx`，網址是否使用 `http://`；目標 Wi-Fi 上無法用此網址開設定頁。 |
| 設定頁顯示 `wifi_connect_timeout` | 核對目標 SSID、密碼與 `2.4 GHz` 支援；保留熱點並修正後重試。 |
| 按「退出連線」後設定頁斷線 | 手動關閉熱點的正常結果；切回目標 Wi-Fi，再開 Dashboard 的相機 QR。 |
| ESP32 已加入 Wi-Fi，Dashboard 仍未連線 | 確認 Dashboard 已選網、裝置可互通、防火牆允許探索與 HTTPS；再使用目前控制端網址作備援。 |
| 手機開不了相機頁 | 使用當次 QR；確認手機與電腦在同一區網、伺服器仍執行，並核對 HTTPS／相機頁診斷。 |
| Arduino 寫入完成，卻找不到 COM 埠 | 依 [燒錄結果與 USB 排查](../環境部署/README.md#4-判斷燒錄結果與-usb-問題) 區分寫入成功與重啟後斷線。 |

## 8. 照片與設定備份

Dashboard 的「開啟資料夾」只開啟目前模式的資料區（見 [資料分區](CAPTURE_SPEC.md#資料分區)）。若使用 junction，另確認其實際目標。

Dataset（含根目錄舊資料）、舊 `Django_Server/detection_results/`、`Django_Server/runtime_config/` 與 `setup.local.h` 均不靠 `git push` 備份。搬電腦前先停止操作並另行備份需要保留的資料與私密設定；ESP32 NVS 是保存在板上的 Wi-Fi 設定，不隨電腦專案複製。
