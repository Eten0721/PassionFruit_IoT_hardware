# 百香果 IoT 系統部署與操作說明

[回到專案首頁](../README.md)

本文是部署與日常操作的入口。首次部署依第 1～5 節完成；環境與韌體已備妥時，直接看「[日常啟動](#6-日常啟動與更換網路)」。開發者與發布 Release 的維護者看[第 9 節](#9-開發者與維護者)。硬體參數、配網安全條件與控制協定以 [CAPTURE_SPEC.md](CAPTURE_SPEC.md) 為準，實作與實機驗收狀態見 [CURRENT_STATUS.md](CURRENT_STATUS.md)。

## 1. 準備電腦與區域網路

- Windows 10／11 電腦；首次安裝需要網際網路。一般使用者不需要事先安裝 Python、Anaconda 或 Git，啟動器會自動準備。
- 電腦、ESP32 與相機手機最後須加入可彼此連線的同一區域網路；ESP32 使用 `2.4 GHz` Wi-Fi，不使用隔離裝置的訪客網路。
- 電腦保留自動取得 IP 與 DNS。部署完成後可驗證沒有網際網路的區網操作，但須保留 Wi-Fi 與裝置互通。
- 初次燒錄先只接 ESP32 與可傳資料的 USB 線。接回馬達前依 [上電前檢查](../record_image/硬體接線與驗收摘要.md#上電前檢查) 完成斷電檢查。

### 先分清楚三種網址

| 用途 | 網址 | 開啟條件 |
|---|---|---|
| ESP32 的 Wi-Fi 設定頁 | `http://192.168.4.1/` | 手機或電腦已連上 `PF-Setup-xxxxxx` 熱點 |
| 電腦本機 Dashboard | `https://127.0.0.1:8000/dashboard/` | 在執行 Django 的同一台電腦開啟 |
| 手機相機頁 | Dashboard 當次顯示的 HTTPS 相機 QR／網址 | 手機已切回與 Django 相同的區域網路 |

`192.168.4.1` 是 ESP32 自己建立的設定熱點位址，目前韌體每次開啟設定熱點都使用這個 IP，不會隨機改變。ESP32 加入目標 Wi-Fi 後取得的 IP，以及 Django 電腦的 IP，則由路由器分配，可能改變。設定頁使用 **HTTP**；Dashboard 與手機相機使用 **HTTPS**。手機不能用 `127.0.0.1` 連到電腦。

## 2. 首次安裝

### 2.1 下載專案

1. 開啟 [Releases](https://github.com/Eten0721/PassionFruit_IoT_hardware/releases)，在最新版本下載 **Source code (zip)**。尚無 Release 時，在專案首頁按 **Code → Download ZIP**。
2. 解壓縮到只含英文與數字的資料夾，例如 `C:\PassionFruit`。不要直接在壓縮檔預覽視窗裡執行。
3. 確認 `Django_Server\models\ROI.pt` 約 20 MB。若只有 1 KB 左右，代表下載到的是 Git LFS 指標而不是模型，請改從 Release 重新下載；啟動器遇到這種情況也會停止並說明。

### 2.2 雙擊啟動系統

雙擊專案根目錄的 **`啟動系統.bat`**。Windows 若顯示「Windows 已保護您的電腦」或安全性警告，確認檔案來自本專案後選「其他資訊」→「仍要執行」，或按「執行」。

第一次執行會依序自動完成：

1. 找不到 conda 時，下載並安裝 Miniforge（約 90 MB，安裝到使用者目錄的 `miniforge3`；使用者名稱含中文時改裝到 `C:\miniforge3`）。已有 Anaconda／Miniconda 時直接沿用。
2. 沒有 `PF` 環境時建立它（Python `3.14.4`）。
3. 安裝 PyTorch 與專案套件：偵測到 NVIDIA 顯示卡時安裝 CUDA `12.8` 版，否則安裝 CPU 版。

首次安裝需要網路，視網速約需 10～30 分鐘。之後每次啟動只比對套件版本，數秒內即可開始檢查；專案更新了套件版本時才會自動補裝。

接著啟動器會檢查模型、LINE 憑證、防火牆規則與連接埠，顯示「推論裝置：cuda」或「推論裝置：cpu」，再啟動 Django 並自動開啟 Dashboard。有 NVIDIA 顯示卡卻顯示 `cpu` 時，先更新顯示卡驅動程式（CUDA `12.8` 需要 `570` 以上版本）；以 CPU 推論仍可運作，只是較慢。

任何一步失敗時，視窗會停住並顯示中文原因與紀錄檔位置 `logs\launcher.log`。依訊息修正後重新雙擊即可，已完成的步驟會自動跳過。

### 2.3 Windows 防火牆

手機與 ESP32 要能連進這台電腦，需允許兩條連入規則。只在可信任的實驗室網路上做一次：

1. 雙擊 **`首次設定防火牆.bat`**，在 Windows 權限提示按「是」。
2. 目前網路若為「公用網路」，畫面會逐一詢問是否改為「私人網路」。只有可信任的實驗室網路才輸入 `Y`；公共 Wi-Fi 一律略過。
3. 腳本只新增尚未存在的規則：TCP `8000` 用於 Django HTTPS，UDP `5353` 用於裝置探索，兩者都限私人網路的同一子網路連入。

保留 Windows 防火牆；路由器也須允許區網裝置互通。換到新的 Wi-Fi 時，若該網路是公用網路，再執行一次此檔案。啟動器偵測到規則缺少時也會提醒。

### 2.4 Demo 設定與資料位置

檢測、分類與硬體流程不需要 `.env` 或手動設定金鑰。**例外是 LINE 通知**（見下方 2.5 節）與選用的 Dashboard 助手（見 2.6 節）。照片與結果存於 `Django_Server/dataset/`，依蒐集與自動檢測分區（分區與舊資料規則見 [資料分區](CAPTURE_SPEC.md#資料分區)）；操作設定與目前模式存於 `Django_Server/runtime_config/`。這些資料由檔案系統保存，不需要執行 database migration。更新版本時須手動搬移，見 [第 8 節](#8-照片設定備份與更新版本)。

Django 每次啟動會自動產生隨機 `SECRET_KEY`。目前未使用登入、Django session 或持久化簽章，因此符合單一程序的區網 Demo；將來加入這些功能或使用多程序部署時，須改用各程序共用且能跨重啟保存的私密金鑰。金鑰用途見 [Django 官方說明](https://docs.djangoproject.com/en/5.2/ref/settings/#secret-key)。

### 2.5 LINE 通知憑證（要使用 LINE 功能必做）

> [!IMPORTANT]
> **沒有放這個檔案，LINE 加工果通知就無法發送。** 檢測與分槽仍可正常運作，但加工果通知只會留在待送，Dashboard 的「LINE 加工果通知」會顯示「尚未完成設定」。啟動器每次啟動都會檢查，缺少時顯示醒目警告。

1. 向**專案擁有者**索取 `notification_credentials.json`。此檔不公開散布。
2. 放到 `Django_Server/runtime_config/notification_credentials.json`；資料夾不存在時先建立。檔名與位置必須完全相同。
3. 關閉啟動器視窗，再重新雙擊 `啟動系統.bat`。
4. 在 Dashboard 展開「目前流程與操作設定」，確認「LINE 加工果通知」沒有出現「尚未完成設定」，再依需要開啟通知。開關依「使用硬體」與「純拍攝」分開，預設都是關閉。

此檔含 LINE bot 權杖與 Cloudinary 金鑰，等同 bot 的密碼：

- 已被 `.gitignore` 忽略，**不要**改名、移到其他資料夾、`git add -f`、貼到聊天群組或截圖。
- 下載 ZIP、`git clone`／`git pull` 都不會帶來這個檔案，換電腦或更新版本時要重新放入。
- 懷疑外洩時，到 LINE Developers 重新發行 token、到 Cloudinary 重新產生 API Key，再由專案擁有者提供新的檔案。

檔案欄位、發送、重試與開關規則見 [檢測資料與 LINE 通知](CAPTURE_SPEC.md#檢測資料與-line-通知)。

### 2.6 Dashboard 助手 Gemini 金鑰（選用）

Dashboard 右下角「問助手」可查詢檢測統計並畫圖、回答本文件的啟動與部署問題，以及以 Google 搜尋回答百香果病蟲害知識。助手只查詢、不能操作機器；**沒有設定時只有助手無法使用**，拍攝、檢測、分槽與瑕疵趨勢提醒照常運作。助手需要這台電腦能上網。

1. 以 Google 帳號登入 [Google AI Studio 的 API keys 頁](https://aistudio.google.com/apikey)，按 **Create API key**，選擇或新建一個 Google Cloud 專案，複製產生的金鑰（`AIza` 開頭）。
2. **連結帳單**：在 AI Studio 的 API keys 頁對該專案按 **Set up billing**（或到 [Google Cloud 帳單](https://console.cloud.google.com/billing) 把專案連結到帳單帳戶），讓專案使用付費層級；付費層級的對話內容不會被用於訓練模型。**農業知識搜尋（Google Search grounding）只有付費層級提供**：免費層級仍可查統計與部署問題，但問病蟲害時聊天框會提示「農業知識搜尋需要 Gemini 付費層級」。新使用者的帳單帳戶可能必須先**預付儲值**（最低 NT$150）才能呼叫 API，餘額為 0 時聊天框顯示「帳單餘額不足」；Google Developer Program 的 GCP 抵免額要在預付後才開始扣抵，涵蓋範圍與到期日以帳單頁為準。
3. **設定預算警示**：在 [Google Cloud 帳單 → 預算與快訊](https://console.cloud.google.com/billing/budgets) 建立預算，範圍選該專案，設定每月金額與 50%／90%／100% 的 email 快訊。預算警示只寄通知、不會自動停用 API，實際上限靠下一步的每日請求上限。
4. 建立 `Django_Server/runtime_config/assistant_credentials.json`（UTF-8），內容如下；`model` 填 AI Studio 模型清單中的模型代碼（舊模型可能不再開放給新使用者，聊天框顯示「模型無法使用」時請改用清單上的代碼），`daily_request_limit` 是每天最多呼叫 Gemini 的次數（一個問題通常 1～3 次，含搜尋），省略時為 `200`：

   ```json
   {
     "gemini_api_key": "AIza...",
     "model": "gemini-3.8-flash",
     "daily_request_limit": 200
   }
   ```

5. 不需重新啟動；在 Dashboard 按「問助手」，問「最近一週四級分布」確認會回覆並顯示圖表。

此檔等同付費帳戶的密碼：已被 `.gitignore` 忽略，**不要**提交、貼到聊天群組或截圖；換電腦或更新版本時與 LINE 憑證一起從舊的 `runtime_config\` 複製。懷疑外洩時，在 AI Studio 刪除該金鑰並重建。聊天框顯示的錯誤原因（未設定、無法連線、達到上限、帳單餘額不足、模型無法使用）與 Gemini 回傳的詳細錯誤（記錄在啟動器視窗的 log）見 [Dashboard 助手](CAPTURE_SPEC.md#dashboard-助手)。

## 3. 啟動 Django 與確認網路

### 3.1 開啟伺服器

雙擊 `啟動系統.bat`。Dashboard 自動開啟後，若瀏覽器顯示憑證警告，選「進階」→「繼續前往」；這是本機自簽 HTTPS 憑證的正常提示。

伺服器執行期間保留啟動器視窗；**關閉視窗或按 `Ctrl+C` 即停止伺服器**。伺服器已在執行時再次雙擊，只會重新開啟 Dashboard。

### 3.2 選擇本次網路

1. 在這台電腦的瀏覽器開啟 `https://127.0.0.1:8000/dashboard/`。
2. 展開頂部「確認本次使用的網路」，選擇目前連線的 Wi-Fi／Ethernet，按「確認使用」。即使只有一個候選，每次 Django 啟動仍要確認。
3. 確認頁面顯示「控制端網址」及相機 QR Code。先記下控制端網址，ESP32 自動探索失敗時會用到。

此時 ESP32 或相機尚未加入而顯示未就緒是正常的；繼續下一節。

## 4. ESP32 首次燒錄與 Wi-Fi 設定

### 4.1 首次燒錄

依 [ESP32 燒錄指南](ESP32燒錄指南.md) 安裝開發板與程式庫、設定私密熱點密碼，再上傳正式韌體。已燒錄支援配網的版本時，日常啟動與換網直接做以下操作。

### 4.2 開啟設定熱點

1. ESP32 正常上電，先讓 BOOT 保持放開。不要按住 BOOT 上電或重置來開設定頁。
2. 沒有已保存的 Wi-Fi 設定時，初始化完成後會自動開熱點；已有設定時，等裝置安全閒置，再按 Dashboard「ESP32 網路設定」的「開啟 ESP32 設定熱點」，或在機台按一下 BOOT。
3. 用手機的 Wi-Fi 設定連上 `PF-Setup-xxxxxx`，輸入 `setup.local.h` 中設定的熱點密碼。尾碼用來辨識裝置。

BOOT 腳位仍須依實際板型核對。送料、拍攝、分類或安全鎖存在時可能拒絕配網；可查看 Dashboard 底部「ESP32 網路設定」的原因。完整條件見 [配網規格](CAPTURE_SPEC.md#esp32-配網與控制端識別)。

### 4.3 手動開啟並保存設定頁

1. 手機保持連上 ESP32 熱點。若手機提示「沒有網際網路」，選擇繼續使用這個 Wi-Fi。
2. 用手機相機掃描 Dashboard「ESP32 網路設定」區的設定頁 QR Code，或打開瀏覽器在**網址列**輸入 `http://192.168.4.1/`。不依賴設定頁自動彈出，也不把網址輸入搜尋框。
3. 按「掃描 SSID」選取目標 Wi-Fi，或直接輸入 SSID；輸入的是**目標 Wi-Fi 密碼**，與前一步的 ESP32 熱點密碼分開。
4. 「手動 Django HTTPS origin」先留空，讓 ESP32 自動探索。需要備援時，填入 Dashboard 顯示的控制端網址，例如 `https://192.168.0.93:8000`；不要附加 `/dashboard/`、`/camera/` 或 API 路徑，也不要照抄範例 IP。
5. 按「連線並保存」。成功時會顯示 `saved` 與取得的 IP，並啟用「退出連線」；設定保存於 ESP32 NVS，重新上電仍保留。
6. 按「退出連線」關閉設定熱點，再手動將手機切回目標 Wi-Fi。手機不一定會自動切回；熱點關閉後原設定頁無法繼續使用是正常的。

密碼錯誤或逾時時，設定熱點會保留，依錯誤訊息修改後重試。不需變更時按「取消設定」或再按一下 BOOT，ESP32 會關閉熱點並恢復原本保存的 Wi-Fi。ESP32 連線目標 Wi-Fi 時，手機可能暫時離開熱點，重新連上 `PF-Setup-xxxxxx` 後設定頁會自動更新。保存 Wi-Fi 不需要等 Django 上線，但硬體運作仍須通過 Django 的就緒與安全檢查。

## 5. 手機相機與第一次操作

1. 確認手機已切回與 Django 相同的區網，用 Chrome 開啟 Dashboard 顯示的相機 QR／網址。
2. 按「開啟相機」並允許權限；確認手機顯示即時畫面、Dashboard 顯示相機就緒。使用期間保持相機頁在前景，不鎖定螢幕。
3. 先選「蒐集模式」＋「純拍攝」，按「開始執行」，檢查三張照片都已保存，再完成人工分類。此模式不操作馬達。
4. 要使用硬體時，先完成 [接線與上電檢查](../record_image/硬體接線與驗收摘要.md#上電前檢查)，確認 ESP32 已連線，再依 Dashboard「停穩設定與送料校正」及 [正式開始條件](CAPTURE_SPEC.md#開始條件) 完成校正。只在全部門檻成立後開始硬體流程。

新 IP、電腦或手機可能遇到 HTTPS 憑證警告或相機權限問題。相容性與安全來源判斷以 [手機與離線驗收前提](CAPTURE_SPEC.md#手機與離線驗收前提) 為準；不能把一次成功視為所有裝置都已驗證。

部署完成的判斷是：Dashboard 已確認網路、相機就緒且三張照片實際保存；硬體模式另需 ESP32 正式連線、送料校正與安全條件成立。只看到 Wi-Fi 已取得 IP 還不夠。

### 5.1 瑕疵趨勢提醒

某類瑕疵在最近一段時間的比例偏高或上升時，系統會在 Dashboard 顯示提醒，並送到 LINE 群組（需完成 [2.5 節](#25-line-通知憑證要使用-line-功能必做) 的憑證設定）。統計範圍是檢測資料中所有已判級的果實。

1. 在 Dashboard 按「目前流程與操作設定」右側的「＋」展開，找到「瑕疵趨勢提醒」區塊。
2. 勾選「啟用趨勢提醒」（預設關閉）。
3. 依需要調整數值，按「保存提醒設定」。提醒只會在下一顆果實判級完成後重新檢查。同一次檢查達標的類別會合併成一則 LINE 訊息；Dashboard 只列出提醒時間、類別與送出狀態，完整內容請看 LINE。

| 欄位 | 意思 | 預設 |
|---|---|---|
| 視窗天數 | 只看最近幾天的果實（1～60 天） | 7 天 |
| 冷卻（小時） | 同一類提醒過後，多久內不再重複發送 | 24 小時 |
| 當日突增倍數、當日最少顆數 | 今天的比例達到過去平均的幾倍、且今天至少有幾顆時，視為突增 | 2 倍、10 顆 |
| 門檻 % | 最近「視窗天數」內，有這類瑕疵的果實佔已判級果實的比例，達到此值就提醒。例：門檻 20%、最近 7 天 50 顆中有 10 顆炭疽病即提醒 | 炭疽病 20%；擦傷、蟲咬、畫圖蟲 30%；色澤異常、皺褶、加工果 40% |
| 上升百分點 | 最近「視窗天數」的比例，比再往前同樣天數高出多少就提醒，以百分點相減計算。例：從 10% 升到 25% 是上升 15 個百分點 | 10～15 |
| 最少顆數 | 視窗內至少要有幾顆已判級果實才判斷，避免樣本太少誤報；比較上升時前後兩段都要達到 | 20 顆 |
| 提醒方向 | 訊息中的建議方向，例如病害防疫、蟲害防治、採收搬運 | 依類別 |

想讓提醒容易觸發（例如展示時），可以調低該類的「門檻 %」與「最少顆數」；只想看某一類時，把其他類別的門檻調到 100%。拍攝時間超過「視窗天數」的資料不會納入提醒，但仍會出現在助手的統計中。詳細規則見 [檢測統計與趨勢提醒](CAPTURE_SPEC.md#檢測統計與趨勢提醒)。

## 6. 日常啟動與更換網路

環境與韌體已部署後，不必重裝套件、重建私密設定或重新燒錄：

1. 電腦連上本次區網，雙擊 `啟動系統.bat`（第 3.1 節）。
2. 在本機 Dashboard 確認本次網路；ESP32 正常上電後使用已保存的 Wi-Fi。
3. 手機加入同一區網，重新開啟本次相機 QR，啟用相機並確認就緒。
4. 依本次拍攝模式檢查開始條件，再按「開始執行」。

更換 Wi-Fi 時，先讓裝置安全閒置，電腦與手機加入新網路，重新確認 Dashboard 介面，再依第 4.2～4.3 節重設 ESP32。只換電腦或 DHCP IP 時，ESP32 會重新探索，手機重新掃目前 QR；曾填手動 origin 且探索不可用時，須更新備援網址。換網不需要修改 Firmware 的 API URL 或重燒。

若上一輪曾失聯、帶果實重啟或有待處理資料，先依 Dashboard 與 [安全復原規格](CAPTURE_SPEC.md#失聯門檻與安全交握) 清理並完成人工確認；重新連線或配網不會解除安全鎖。

## 7. 常見問題

| 現象 | 直接檢查 |
|---|---|
| 找不到 ESP32 設定熱點 | 核對 `setup.local.h` 的熱點密碼、正常上電後的 BOOT 操作與配網阻擋原因；缺少有效密碼會回 `setup_ap_failed`，裝置連線時 Dashboard「ESP32 網路設定」也會顯示。 |
| `192.168.4.1` 打不開 | 手機是否仍連著 `PF-Setup-xxxxxx`，網址是否使用 `http://`；目標 Wi-Fi 上無法用此網址開設定頁。 |
| 設定頁顯示 `wifi_auth_failed`、`wifi_ssid_not_found` 或 `wifi_connect_timeout` | 依序核對目標 Wi-Fi 密碼、SSID 與 `2.4 GHz` 支援、訊號；保留熱點並修正後重試。 |
| 按「退出連線」或「取消設定」後設定頁斷線 | 手動關閉熱點的正常結果；切回目標 Wi-Fi，再開 Dashboard 的相機 QR。 |
| 設定頁回 `setup_ap_only` | 請求不是從設定熱點進來；手機須連上 `PF-Setup-xxxxxx` 再開 `http://192.168.4.1/`。 |
| ESP32 已加入 Wi-Fi，Dashboard 仍未連線 | 確認 Dashboard 已選網、裝置可互通、防火牆允許探索與 HTTPS；再使用目前控制端網址作備援。 |
| 手機開不了相機頁 | 使用當次 QR；確認手機與電腦在同一區網、伺服器仍執行，並核對 HTTPS／相機頁診斷。 |
| LINE 通知顯示「尚未完成設定」或群組沒收到 | 確認已依 [2.5 節](#25-line-通知憑證要使用-line-功能必做) 放好 `Django_Server/runtime_config/notification_credentials.json` 並重新雙擊啟動器；再確認目前模式的通知開關已開啟，並查看 Dashboard 顯示的最近錯誤。 |
| 啟動器顯示「模型只有 Git LFS 指標」 | 下載到的 ZIP 不含模型；改從 [Releases](https://github.com/Eten0721/PassionFruit_IoT_hardware/releases) 重新下載，並確認 `ROI.pt` 約 20 MB。 |
| 啟動器顯示「連接埠 8000 目前無法使用」 | 關閉其他 Django 視窗；若沒有其他 Django，通常是 Windows 暫時把 8000 分配給其他程式的連線，等候約 1 分鐘再雙擊，持續發生時重新開機。 |
| 首次安裝中途失敗或網路中斷 | 恢復網路後重新雙擊，已完成步驟會跳過；仍失敗時將 `logs\launcher.log` 交給團隊。 |
| Arduino 寫入完成，卻找不到 COM 埠 | 依 [燒錄結果與 USB 排查](ESP32燒錄指南.md#4-判斷燒錄結果與-usb-問題) 區分寫入成功與重啟後斷線。 |

## 8. 照片、設定備份與更新版本

Dashboard 的「開啟資料夾」只開啟目前模式的資料區（見 [資料分區](CAPTURE_SPEC.md#資料分區)）。若使用 junction，另確認其實際目標。

Dataset（含根目錄舊資料）、舊 `Django_Server/detection_results/`、`Django_Server/runtime_config/` 與 `setup.local.h` 均不靠 `git push` 備份。搬電腦前先停止操作並另行備份需要保留的資料與私密設定；LINE 通知憑證以專案擁有者提供的檔案為準；ESP32 NVS 是保存在板上的 Wi-Fi 設定，不隨電腦專案複製。

以 ZIP 安裝的電腦更新到新版本時：

1. 關閉啟動器視窗，確認沒有進行中的拍攝或分類。
2. 下載新版 ZIP，解壓縮到**新的**資料夾，不要覆蓋舊資料夾。
3. 從舊資料夾複製 `Django_Server\dataset\` 與 `Django_Server\runtime_config\`（含 LINE 憑證與校正設定）到新資料夾的相同位置。
4. 雙擊新資料夾的 `啟動系統.bat`。`PF` 環境會沿用，只有套件版本變更時才補裝。
5. 確認照片、設定與 LINE 通知都正常後，才刪除舊資料夾。

## 9. 開發者與維護者

### 9.1 手動建立開發環境

開發、測試或修改程式時使用 Git checkout，而不是 ZIP。需要 Git、Git LFS 與 Anaconda／Miniconda／Miniforge：

```powershell
git lfs install
git clone https://github.com/Eten0721/PassionFruit_IoT_hardware.git
cd PassionFruit_IoT_hardware
git lfs pull
conda create -n PF python=3.14.4 pip -y
conda activate PF
python -s -m pip install -r Django_Server/requirements-torch.txt --index-url https://download.pytorch.org/whl/cu128
python -s -m pip install -r Django_Server/requirements.txt
```

沒有 NVIDIA 顯示卡時把 `cu128` 換成 `cpu`。PyTorch 版本只維護在 [requirements-torch.txt](../Django_Server/requirements-torch.txt)，啟動器依此判斷是否需要重裝。Python `-s` 避免使用者層套件遮蔽 `PF` 內的版本。開發機一樣可以雙擊 `啟動系統.bat`；手動啟動則在 `Django_Server` 執行 `python -s manage.py check` 後執行 `python -s manage.py runsslserver 0.0.0.0:8000 --noreload`。

啟動器分為 `啟動系統.bat`（入口）、[scripts/launcher.ps1](../scripts/launcher.ps1)（conda 與 `PF`）與 [scripts/launch.py](../scripts/launch.py)（依賴、檢查與啟動）；選擇此架構的原因見 [ADR-0021](adr/0021-double-click-launcher-and-release-zip.md)。修改啟動器後，在已啟用 `PF` 的終端機於 Repository 根目錄執行：

```powershell
python -s -m unittest discover -s scripts -p "test_*.py"
```

### 9.2 發布 Release

一般使用者從 Release 下載 ZIP，因此 `main` 有需要交付的變更時就發布新版本。

**一次性設定**：repo **Settings → General**（側欄最上方，不是 Actions 底下的 General）→ 捲到 **Archives** → 勾選 **Include Git LFS objects in archives**。沒有勾選時，ZIP 內的模型只會是 LFS 指標。

**每次發布**：

1. 確認要發布的 PR 都已合併到 `main`，且已依 [AGENTS.md](../AGENTS.md#驗證要求) 完成驗證。
2. 在 repo 首頁右側點 **Releases → Draft a new release**。
3. **Choose a tag** 輸入 `main` 最新 commit 標題上的版本號（例如 `v1.3.0`；編號規則見 [AGENTS.md](../AGENTS.md#版本與-commit-格式)），選 **Create new tag on publish**，Target 選 `main`。
4. 標題填版本號，按 **Generate release notes** 自動列出合併的 PR，必要時補一句這版的重點與是否需要更新韌體。
5. 按 **Publish release**。

已安裝 GitHub CLI 時，可改在 `main` 上執行 `gh release create v1.3.0 --target main --generate-notes`。

發布後到 Release 頁下載 **Source code (zip)**，確認 `Django_Server\models\ROI.pt` 約 20 MB，且解壓縮後雙擊 `啟動系統.bat` 可開啟 Dashboard。每次 ZIP 下載約使用 64 MB 的 Git LFS 頻寬，可在個人 **Settings → Billing and licensing** 查看用量。
