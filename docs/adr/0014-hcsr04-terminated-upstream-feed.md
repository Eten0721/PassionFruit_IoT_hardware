# ADR-0014：HC-SR04 終止上游送料

- Status: Accepted；機構背景由 ADR-0015 取代
- Date: 2026-07-30

> 後續狀態（2026-08-09）：Issue #11 已將本 ADR 的停止契約接入 production `feed_one`，並以 runtime 安全條件開放正式自動運轉；機構校正與連續運轉仍依實機驗收項目執行。下方「本階段只實作 calibration」保留為當時的漸進開放紀錄，不代表目前軟體狀態。

## Context

連續旋轉 SG90 沒有位置回授，送料桿受外力、負載、電壓與摩擦影響後，固定時間無法穩定對應同一角度。本 ADR 制定時的送料盤使用兩個相隔 `180°` 的落果洞，並以半圈間距作為停止緩衝；該機構背景已由 [ADR-0015](0015-integrated-radial-paddle-feeder.md) 的一體式徑向撥料送料筒取代。安全優先順序仍是寧可漏送，也不能一次送出兩顆。

## Decision

正式送料改由一次有效的 `HC-SR04 <= 6 cm` 讀值正常終止：ESP32 先在本機寫入停止脈波，再以同一筆鎖存事件完成 `feed_one` 並啟動既有首站流程。送料前只接受有效距離 `> 8 cm` 的清空狀態；`0 cm`／Echo timeout 是感測器異常，送料前拒絕命令，送料中則立即停止並暫停。

`feeder_max_run_ms` 是唯一的安全逾時值，不另設隱藏上限或正常運轉時間。逾時與感測落在同一控制迴圈時以逾時優先；ESP32 立即停止、Django 暫停自動送料且不自動補轉。逾時後才抵達的果實仍完成三站拍攝與分類，但系統不自動送下一顆。測試送料共用相同停止條件，成功後只開放人工確認恰好一顆，不建立 Capture session。

送料 runtime profile 只保留停止脈波、驅動脈波與最大運轉時間。驅動脈波可位於停止脈波任一側，以支援馬達換位；兩值只禁止相等。任何參數變更都撤銷送料校正，設定由 Django 原子保存並在 Dashboard 顯示實際運轉時間、停止原因及設定上限。

本階段只實作 calibration `feed_one`，正式自動運轉暫時停用。只有相同 runtime profile revision 的 HC-SR04 測試成功，Dashboard 才允許人工確認校正；修改任一送料參數即取消資格。正式 production 流程需待實機驗證後另行開放。

## Consequences

HC-SR04 成為正常送料終止所必需的回授；感測器異常會犧牲當次送料以避免雙送。正式驅動脈波與最大運轉時間必須依現行機構實測；一體式送料筒的幾何與驗收條件見 [ADR-0015](0015-integrated-radial-paddle-feeder.md)。此 ADR 取代 ADR-0013 的固定計時送料終止條件；Django 中央協調、command 冪等與重新啟動不重送原則維持不變。
