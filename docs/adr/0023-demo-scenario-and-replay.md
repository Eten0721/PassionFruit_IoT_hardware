# ADR-0023：示範情境分區與重播已拍攝結果

- Status: Accepted（目標決策，尚未實作驗收）
- Date: 2026-10-16

## Context

[ADR-0022](0022-dashboard-gemini-assistant.md) 的趨勢提醒與統計問答需要一段時間累積的檢測資料，例如至少 20 顆已判級果實與兩個 7 天視窗；現場 Demo 與手邊都沒有數十顆百香果，無法在現場湊出足以觸發提醒的資料。現場拍攝也受光線、網路與手機狀態影響，不適合做為展示的唯一來源。

## Decision

新增與正式資料完全隔離的「示範情境」，並以重播已拍攝結果在現場觸發提醒。

- **獨立分區**：示範資料存放在 `DATASET_ROOT/demo/`，目錄結構與檢測分區相同；不寫入、不改動 `collection/` 與 `detection/`，也不併入正式統計。Dashboard 只在閒置、沒有任何處理中工作或鎖時，才能切換「示範資料模式」。切換狀態以原子方式保存於 runtime，重啟後恢復。示範模式期間，頁面持續顯示「示範資料」標示。
- **不驅動硬體**：示範模式不建立 motor command、不開始拍攝，也不接收上傳；`/api/state/` 明確回報 `demo_mode`。
- **模擬紀錄**：以管理指令依情境參數產生模擬紀錄，`capture_time` 以執行當下往回推算，讓視窗在 Demo 當天有效。每筆 `result.json` 都有 `simulated: true`，總表標示 `classification_source=simulated`，只保存統計所需欄位，不產生照片。預設情境讓炭疽病比例逐週上升，並停在門檻前一顆；指令產生資料後，以 ADR-0022 的同一套規則自我檢查「目前未觸發，再加一顆炭疽病果實就會觸發」，不成立時拒絕產生。可重新產生以重置情境。
- **重播已拍攝結果**：Dashboard 在示範模式提供「重播一筆已拍攝結果」，只能選擇檢測分區中已保存原圖的果實（建議 fruit_001、fruit_020，三個視角皆偵測到炭疽病）。重播會將原圖複製到示範分區，並在本機重新執行完整的 YOLO 推論與 XGBoost 判級，再以新的 `result_id` 與當下時間保存為示範結果，標記 `replayed_from` 與 `simulated: false`。保存後觸發與正式流程相同的後續處理：結果卡、加工果通知與趨勢提醒檢查。
- **提醒與通知**：示範分區統計所有輪次，不區分硬體選項；開關、冷卻期與待送紀錄與正式模式分開。LINE 訊息第一行以「示範」開頭（例如「示範 |趨勢提醒|」），並註明資料為模擬情境。
- **助手**：示範模式下，統計工具只讀示範分區；系統指示要求回答時說明這是示範資料，不得說成真實產量。

## Consequences

Demo 可以在沒有果實、沒有手機的情況下穩定重現「資料累積、現場一顆觸發提醒、LINE 群組收到通知、助手畫出趨勢圖」的完整流程，並且只動用真實模型推論，不偽造單顆結果。代價是多了一個資料分區與模式切換，Dataset 清理、重置與照片 URL 需涵蓋 `demo`；模擬紀錄的瑕疵比例由情境參數決定，不代表任何真實果園，簡報時必須明確說明。重播依賴檢測分區中已保存的原圖，重置檢測分區後就無法重播。
