# ADR-0023：Demo 預備檢測資料與純拍攝納入開關

- Status: Accepted（目標決策，尚未實作驗收）
- Date: 2026-10-16

## Context

[ADR-0022](0022-dashboard-gemini-assistant.md) 的趨勢提醒與統計問答需要一段時間累積的檢測資料，例如至少 20 顆已判級果實與 7 天視窗；發表會現場只有約 10 顆百香果，無法臨時累積出足以觸發提醒的資料。外部資料集 `D:\passion-fruit-datasets\pf-20260716-v001\` 已有各級果實的三視角照片，可做為預備資料的來源。曾考慮另設示範模式、示範分區與重播按鈕，但會增加模式切換與資料分區規則，使用者也只需要「事先放好資料，再由現場果實接續」。

## Decision

不新增示範模式或資料分區；預備資料直接放入正式的檢測分區，由 Django 照常讀取。

- **產生指令**：以管理指令從外部資料集隨機挑選 N 顆（可指定各級顆數），在本機執行完整的四模型推論與 XGBoost 判級，輸出成與檢測分區相同結構的資料夾（`results/`、`detection_summary.csv` 與 counter），供使用者複製到 `Django_Server/dataset/detection/`。拍攝時間依參數分散在指定日期往前的數天內，讓 7 天視窗在 Demo 當天有效。資料來源只讀不寫；照片與結果不進 Git。
- **誠實標記**：預備資料維持真實的 `hardware_mode=photo_only`，`result.json` 另記 `prepared_from`（資料集、原 fruit_id、原始照片時間），並註明拍攝時間經過調整；推論與判級結果不經人工修改。
- **編號接續**：輸出的 counter 必須讓 Django 之後配發的 `fruit_id` 不與預備資料衝突；指令也拒絕輸出到已有資料的目錄，避免覆寫正式結果。
- **純拍攝納入開關**：統計與趨勢提醒新增一個「包含純拍攝」開關，預設關閉；開啟後，統計工具、助手與趨勢提醒都會把純拍攝與使用硬體的已判級果實合併計算。此設計取代「依硬體選項分開計算提醒」。純拍攝輪次的 LINE 提醒仍在開頭標示「測試」；開關開啟時，訊息註明統計含純拍攝資料。
- **不做重播按鈕**：現場以實際硬體或純拍攝檢測果實，接續預備資料觸發提醒。

## Consequences

Demo 只需事先執行一次指令並複製資料夾，現場不用切換任何模式，現場果實就會與預備資料一起統計並觸發提醒；所有單顆結果都來自真實模型推論。代價是預備資料混在正式檢測分區中：Demo 後若要恢復純淨資料，須以 Dashboard 重置檢測分區，或事先備份並還原。拍攝時間經過調整，簡報時須說明資料是以既有照片預先產生。「包含純拍攝」開關若在正式運轉時忘記關閉，統計會混入測試資料，因此 Dashboard 需持續顯示開關狀態。
