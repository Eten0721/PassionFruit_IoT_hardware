# ADR-0023：Demo 預備檢測資料與統計預設計入所有輪次

- Status: Accepted
- Date: 2026-10-16

## Context

[ADR-0022](0022-dashboard-gemini-assistant.md) 的趨勢提醒與統計問答需要累積的檢測資料，例如至少 20 顆已判級果實；發表會現場只有約 10 顆百香果。現有檢測紀錄全是純拍攝，而統計原本預設只計使用硬體的輪次，導致助手對「加工果有幾顆」回答 0 顆，與 Dashboard 上看到的結果不符。曾評估示範模式、獨立示範分區、重播按鈕、預備資料產生指令與「包含純拍攝」開關；但使用者只需要「事先放好資料，照常讀取」，這些機制只會增加模式與規則。

## Decision

- **不新增 Demo 機制**：不設示範模式、示範分區、重播按鈕、產生指令或額外開關。預備資料直接放進正式的檢測分區 `Django_Server/dataset/detection/`，Django 與助手照常讀取。
- **預備資料的產生方式**：由外部資料集 `D:\passion-fruit-datasets\pf-20260716-v001\` 的四個級距資料夾隨機挑選果實，以正式部署模型實際推論與判級，`fruit_id` 接續既有編號，拍攝時間記錄實際檢測時間，`hardware_mode=photo_only`，結果不經人工修改。來源對照另存於壓縮檔的 `manifest.csv`，不寫入 `result.json`，維持結果契約不變。壓縮檔由使用者自行保存在 Repository 之外。
- **統計預設計入所有輪次**：統計 API、助手工具與趨勢提醒預設納入使用硬體與純拍攝的已判級果實，使用者明確要求時才只看使用硬體的輪次；純拍攝參與觸發的 LINE 趨勢提醒第一行為「測試 |趨勢提醒|」。

## Consequences

Demo 只需事先放入資料，現場果實會與預備資料一起統計並觸發提醒，所有單顆結果都來自真實模型推論。純拍攝測試會混入日常統計；正式運轉前，若要只看實機資料，須在提問時指定只看使用硬體的輪次，或重置檢測分區。預備資料的拍攝時間是產生當天，超過 7 天後就不再參與趨勢提醒；Demo 前若需要，應重新產生一批。
