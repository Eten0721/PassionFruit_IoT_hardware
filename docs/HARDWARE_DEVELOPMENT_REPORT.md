# 三閘門與分類器硬體開發紀錄

更新日期：2026-07-14

## 紀錄目的

本文件整理三站百香果拍攝軌道在實作過程中遇到的機構問題、改良方式與設計理由，作為後續實機校正、維修與設計迭代的參考。現行系統仍以「果實於站點停穩、手機單張照片保存成功後，才放行下一閘門」為核心安全規則；硬體改良的目的，是讓百香果能更可靠地停留與移動，而不是以固定延遲取代拍攝完成確認。

## 初期單桿閘門

初期的三個閘門皆由一根直桿構成。直桿能攔住一般姿態的百香果，但伺服馬達旋轉放行時，只能從單一接觸點帶動果實，因此實測時出現以下問題：

- 百香果可能停在兩個站點之間，無法順利滾到下一個閘門。
- 果實外形並非規則球體，直桿施力後可能只讓果實偏轉，沒有形成足夠的前進推力。
- 百香果若保留蒂頭，蒂頭可能與軌道或桿件互相干涉，使果實卡住或無法轉動。

## 改良為 L 型閘門

為改善果實卡在半途及帶蒂頭時不易轉動的問題，後續將每個閘門改為 L 型結構。L 型閘門在伺服馬達旋轉時，果實後方仍會保留另一段桿件持續接觸並推動果實，使旋轉動作不只是解除阻擋，也能提供較明確的前進力量。

這項改良可以降低百香果停在站點之間的機率，並提升不同尺寸、形狀及蒂頭方向下的通過穩定性。L 型桿仍須配合軌道寬度與馬達角度校正，避免推力位置過高或過低。

## 相鄰閘門的高度錯位

三組 L 型桿相鄰配置後，旋轉範圍會比單根直桿更大。若三顆馬達安裝在相同高度，相鄰的 L 型桿可能在動作途中互相碰撞，造成伺服馬達受阻、桿件偏移，甚至影響歸位角度。

目前的處理方式是將中間馬達墊高約一個桿件厚度，使中間閘門與前後兩組閘門形成高度錯位。如此可讓相鄰 L 型桿的旋轉路徑彼此錯開，降低碰撞風險，同時保留三站原有的位置與功能。

## 馬達安裝高度調整

三顆馬達安裝在ㄇ型鐵的凹槽位置。初期安裝高度較高，使閘門桿件接觸到百香果的上方；當接觸點過高時，桿件可能從果實上方掠過，或只能推動果實傾斜，無法產生足夠的水平推力。

後續降低馬達排列與閘門的整體高度，讓桿件更接近百香果的有效受力位置。調整後應同時確認：閘門歸位時能確實攔住果實、放行時能推動果實，以及桿件不會刮到軌道底板。

## HC-SR04 安裝位置調整

HC-SR04 超音波感測器原先設置於軌道右側，但該位置接近閘門的旋轉範圍，存在被桿件撞擊的風險。後續將感測器移至軌道左側，使其避開 L 型閘門的動作路徑，同時保留偵測百香果進入拍攝軌道的功能。

調整位置後仍須確認感測方向與軌道對齊，並避免ㄇ型鐵、側邊導軌或其他固定件進入超音波量測範圍。HC-SR04 的 Echo 訊號接到 ESP32 前，仍必須先降壓至安全的 `3.3 V` 邏輯電位。

## MG996R 分類機構

三站拍攝完成、Gate 3 放行、三個 SG90 歸位並回報 `capture_sequence_finished` 後，使用者才會在 Dashboard 進行人工分類。Django 先完成照片資料夾搬移、`metadata.csv` 與 counter，再透過同一個 motor command slot 下發 `classify_fruit`；MG996R 不參與前三站拍攝或 Gate 3 的安全交握。

目前 MG996R 硬體與動作基準：

| 項目 | 設定 |
| --- | --- |
| 控制腳位 | GPIO `25` |
| Home | `85°` |
| 上中等 | `25°` |
| 下等 | `55°` |
| 加工 | `115°` |
| 廢棄 | `145°` |
| 分類位置保持 | `1000 ms` |
| 歸位穩定 | `500 ms` |
| firmware 動作 timeout | `5000 ms` |

MG996R 必須使用足以供應伺服瞬間電流的獨立外部電源，且電源地必須與 ESP32、三個 SG90 及 HC-SR04 共地；不得由 ESP32 的供電腳直接驅動。分類器目前沒有位置回授，因此 `classification_sorter_completed` 只代表控制時序完成並成功回報，不能證明機械已實際到達角度。

實機驗收應逐一確認四個分類角度、Home 歸位、未知分類代碼只嘗試回 Home、相同 command ID 不重複作動，以及斷網後只重送 report、不重新轉動。分類期間也必須確認主迴圈、Wi-Fi 與 command/report retry 持續執行，且三個 SG90 不會被分類器錯誤復原流程驅動。

## 目前成果與後續驗證

目前拍攝機構已由單桿閘門改為 L 型閘門，並完成中間馬達墊高、整排馬達降高及 HC-SR04 移位；後段另以獨立 MG996R 執行人工分類結果。三站 SG90 與 MG996R 在 firmware 中由不同 controller 管理，不共享角度或錯誤復原流程。

後續實機驗證應包含：

1. 使用不同尺寸、形狀及蒂頭方向的百香果，確認三站皆能順利攔截與放行。
2. 以低速或高速錄影確認相鄰 L 型桿在完整旋轉範圍內不會碰撞。
3. 確認第 2、3 站回報 ready 前，百香果已停止滾動，且沒有停在兩站之間。
4. 確認 HC-SR04 不會被閘門撞擊，並重新量測移位後的觸發距離穩定性。
5. 檢查多次循環後，馬達墊高件、ㄇ型鐵與桿件固定處是否鬆動。
6. 逐一量測 MG996R 四個分類位置與 Home，觀察外部電源壓降、卡點、溫升及 ESP32 是否重啟。
7. 以 Serial log 與高速錄影確認 MG996R 動作不會改變 Gate 3 放行、三閘門歸位或下一次自動觸發的互斥規則。

## 實測延遲基準

配合目前機構的實測結果，完整 timing profile 的五項初始推薦值如下：

| 設定 | 推薦值 | 用途 |
| --- | ---: | --- |
| `first_station_settle_ms` | `300 ms` | HC-SR04 觸發後，等待第 1 站果實停穩 |
| `servo_settle_ms` | `200 ms` | 等待伺服馬達完成放行動作 |
| `fruit_settle_ms` | `350 ms` | 等待果實抵達下一站並停止滾動 |
| `final_gate_return_delay_ms` | `300 ms` | 第 3 站放行後，等待果實離開再讓閘門歸位 |
| `idle_command_poll_interval_ms` | `250 ms` | ESP32 閒置時向 Django 取得拍攝或人工分類命令的間隔 |

前四項屬於機構動作與果實停穩時間；`idle_command_poll_interval_ms` 只控制閒置命令輪詢頻率，可在 `100～5000 ms` 間以 `50 ms` 為步進調整。這些數值是新環境、首次刷入或 runtime 設定遺失時的推薦起點；現場仍可透過 Dashboard 在系統 idle 時進行校正。無論延遲設定為何，系統都必須維持「Django 確認當站照片保存成功後，才放行下一閘門」的交握規則。
