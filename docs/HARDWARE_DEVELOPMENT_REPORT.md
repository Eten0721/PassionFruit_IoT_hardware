# 送料、三閘門與分類器硬體開發紀錄

更新日期：2026-08-12

## 紀錄目的

本文件只保存送料與拍攝軌道的機構演進、實測觀察與維修資訊。GPIO、角度、timing、command 與分類 code 統一參考 [DATA_COLLECTION_SPEC.md](DATA_COLLECTION_SPEC.md)。

## 平台基準

目前平台斜面總長約 `47 cm`，短邊高約 `5 cm`、長邊高約 `18 cm`，整體傾斜角約 `16°`。這些是現有機構的實測基準；更換平台或支架後應重新量測，不可直接沿用。

## 初期單桿閘門

初期三個閘門都使用單根直桿。它能攔住一般姿態的果實，但放行時只有單一接觸點，實測出現：

- 果實停在兩站之間。
- 不規則外形只被推偏，沒有持續向前。
- 蒂頭與軌道或桿件干涉。

![初期使用單根直桿的三閘門配置](images/hardware-development/initial-single-rod-gates.png)

## 改良為 L 型閘門

後續改為 L 型結構，旋轉時由後方桿件持續接觸並推動果實，降低停在站點之間的機率。L 型桿仍須配合軌道寬度與接觸高度校正，避免推力位置過高或刮到底板。

![改良後的 L 型閘門與整體安裝配置](images/hardware-development/improved-l-shaped-gates.png)

## 相鄰閘門高度錯位

三組 L 型桿的旋轉範圍較大，相同安裝高度會使相鄰桿件碰撞。中間馬達目前墊高約一個桿件厚度，讓旋轉路徑錯開。維修後必須完整轉動三組閘門，確認沒有干涉或固定件鬆動。

## 馬達安裝高度

初期馬達過高，桿件容易從果實上方掠過或只使果實傾斜。降低整排馬達後，接觸點更接近有效受力位置。調整時同時確認歸位能攔截、放行能推動，且桿件不刮軌道。

目前卡果主要發生在第 2 閘門前往第 3 閘門的路段，拍攝與分類功能仍可正常運作。下一次機構調整將降低三個閘門高度並延長閘門桿，目標是讓接觸點更穩定地推動不同尺寸、外形與蒂頭方向的果實；調整後必須重新執行三站停穩與桿件干涉驗收。

## HC-SR04 位置

感測器原先位於軌道右側，接近閘門旋轉路徑；後續移到左側以避開撞擊。移位後需重新檢查感測方向、固定件反射與觸發穩定性。電壓安全與分壓量測見 [`hardware_notes/硬體接線與驗收摘要.md`](../hardware_notes/硬體接線與驗收摘要.md)。

## 上游單顆送料機構

早期送料機構使用獨立漏斗與具有兩個落果洞的旋轉送料件，兩個洞在旋轉路徑上相隔 `180°`。2026-08-08 改採一體式送料筒：圓筒同時儲存百香果，底部中央的 360° MG996R 帶動四片徑向撥片，將筒底果實推向寬 `9 cm` 的側面出口。出口上方擋板下緣距底板 `9 cm`，並向筒內延伸 `9 cm`，用來限制多顆果實同時靠近出口及容納蒂頭。新版沒有落果孔，不再以半圈孔位間距作為停止餘裕。

送料筒目標內徑為 `20～22 cm`、內部高度為 `30 cm`。MG996R 不穿過底板，馬達本體直立於筒底中央，高度約 `4.5 cm`，底座占地約 `4 × 2 cm`；受製作方式限制，馬達本體直接接觸果實。四片撥片採可拆換、具有垂直接觸面的圓角構型，下緣接近底板但不得摩擦，接觸高度需涵蓋果實下半部；目標長度為 `9～9.5 cm`，實際長度需依筒內徑保留不碰壁的旋轉間隙。送料筒頂部保持開放。馬達底座旁另留線材孔，電源線與訊號線直接離開送料筒，筒內不得留下可能被果實或撥片勾住的線圈與接頭。

側面出口直接對齊拍攝平台起點，不另設導料斜道；出口底部與拍攝平台起點的高低差為 `8.5～9 cm`。此高低差以容納一顆百香果並降低落差為目標，仍需用混合果形實測滾落方向、蒂頭干涉與果皮撞傷。

固定時間控制的實測問題是送料件受外力後會偏離原角度，後續相同運轉時間可能推不到果實。新策略不再追求固定角度：第一筆有效 HC-SR04 觸發同時代表果實抵達與正常停止。人體感覺落果至觸發幾乎同時發生，但正式餘裕必須以 Firmware 記錄的實際運轉時間、停止原因與高速錄影驗證，不採用體感毫秒數。

SG90 原型的歷史估算使用 TowerPro 標示的 [4.8 V 時 `110 RPM`、6 V 時 `130 RPM`](https://towerpro.com.tw/product/sg90-360-degree-continuous-rotation-servo/)，半圈約為 `231～273 ms`。這些速度與時間只適用於舊 SG90，不得沿用至 MG996R。

2026-08-03 決定將現行送料目標改為 [360° MG996R](https://towerpro.com.tw/product/mg995-robot-servo-360-180-rotation/)。原廠標示 MG996R 重量 `55 g`、尺寸 `40.7 × 19.7 × 42.9 mm`、堵轉扭力為 4.8 V 時 `9.4 kg/cm`、6.0 V 時 `11 kg/cm`；舊 SG90 為 `9 g`、`23 × 12.5 × 22 mm`。安裝前必須重新確認固定座強度、舵盤齒規、送料盤同心度、完整旋轉路徑與漏斗干涉，不能直接沿用 SG90 固定方式。

更換馬達不改變控制契約：仍使用 GPIO `23`、可校正的停止與驅動脈波、HC-SR04 正常停止及最大運轉時間保護。驅動方向會隨馬達安裝位置與脈波位於停止值的哪一側改變，不固定為順時針；接近停止死區時也可能因滿載摩擦而無法起轉。

校正與裝載驗證順序：

1. 確認送料筒、MG996R、四片撥片、出口與擋板沒有鬆動或干涉，撥片完整旋轉時不碰筒壁。
2. 空送料筒調整停止脈波，確認馬達沒有爬行。
3. 確認空感測區能取得有效且大於重新待命門檻的距離；`0 cm` 必須視為感測器或線材異常。
4. 放入 `10` 顆，連續執行 `10` 次「測試送料一次」且不補回已送出的果實，覆蓋剩餘量由 `10` 顆降至 `1` 顆的情境。
5. 自行調整停止脈波、驅動脈波與最大運轉時間；驅動脈波需找到能可靠撥動果實且不造成雙送的最慢值，最大運轉時間以 `5000 ms` 為推薦起點、範圍為 `1000～20000 ms`、調整間距為 `500 ms`，最終值由操作員依實測自行指定。
6. 每次記錄實際運轉時間、停止原因、漏送、雙送、卡料及撥片是否停滯；任一次失敗都要在調整後將同一批果實放回，從 `10` 顆重新累計。
7. 現階段只驗證 `10` 顆裝載量；超過 `10` 顆與正式安全填料線都維持未驗證，不使用「滿載」描述送料能力。
8. 測試成功觸發 HC-SR04 後，在 Dashboard 確認單顆送料，才允許正式自動運轉。

十顆樣本應盡量涵蓋不同大小、形狀與蒂頭方向，並記錄各顆最大橫向直徑；樣本外形過於相近時只能完成基本功能驗證。每次果實都必須落在拍攝平台起點範圍內，不得彈出軌道、越過 Gate 1、勾住出口或產生可見破皮與凹傷。實機記錄另需保存撥片材料、數量、固定方式、長度、厚度、垂直高度、底板間隙、筒壁最小間隙、舵盤與螺絲規格，以及連續運轉後是否鬆動、變形或刮傷果實。

最大運轉時間只處理感測未觸發的異常，不是正常停止時間。若它先到，或送料中 HC-SR04 無回音，馬達立即停止且不得自動補轉。若逐級裝載或混合果形測試出現雙送、卡料、撥片停滯或無法可靠起轉，先調整驅動脈波、撥片與筒壁間隙、出口擋板及側面出口幾何；仍無法通過時再評估改用具有單顆容納槽的計量轉子。

最大運轉時間到期時，Dashboard 顯示「進料未確認：請檢查送料筒是否缺料或卡料」，自動送料保持停用。十顆送料完成後至少執行一次不提前中止的空筒測試，確認 ESP32 能在指定上限本機停止並回報 `feeder_max_run_timeout`。

Dashboard 維持既有「優雅暫停」，只禁止後續送料，不中止正在旋轉的 `feed_one`。正常清料必須等待 HC-SR04 或最大運轉時間使 ESP32 回報目前送料已停止，並目視確認撥片靜止；關閉送料專用電池盒 C 只保留給緊急狀況。

緊急關閉電池盒 C 後，若 Dashboard 仍可連線，操作員先要求優雅暫停，保持斷電直到目前 `feed_one` 回報 `feeder_max_run_timeout`，清料且手離開送料筒後才重新送電。若無法連線或看不到 report，則保持電池盒 C 關閉，清料後重新啟動 ESP32，等待 Firmware 初始化並確認 Dashboard 顯示 ESP32 已連線、正式運轉仍停用，再重新送電。兩條路徑都必須先執行一次測試送料，才能恢復正式運轉。

## 2026-08-12 實機測試紀錄

### 已觀察事實

- Dashboard 建立 `feed_one` 後，曾出現送料 360° MG996R 沒有實際轉動，但計時到達上限並回報 timeout；重新關閉再開啟原電池盒開關後曾暫時恢復，之後仍偶發未起轉。
- 在馬達能正常運轉時，HC-SR04 可停止送料，三站能階梯式拍攝三張照片，人工分類後位置型 MG996R 正常轉向，送料 MG996R 也能進入下一輪。
- 舊 Dashboard 的操作順序容易被理解成「套用 → 測試 → 勾選 → 再測試／再套用」；實際上 checkbox 原本沒有立即保存，造成重複測試的操作誤解。
- 手機直向影像會依視窗縮放，但 Dashboard 固定 `16:9` 預覽外框造成額外黑邊或留白。
- 拆裝平台時發生一次原因不明的放電／電擊感，電腦螢幕一度黑屏後恢復。其後舊 ESP32 的 CH340 仍可被電腦枚舉為 serial port，但無法取得 ROM bootloader 回應，手動進入下載模式仍無效；該板停止使用，不再接回系統。

### 尚未驗證的供電推論

MG996R 未起轉與重新切換電池盒開關後暫時恢復，可能與動作時電壓下降、電池盒開關／接點電阻或電池盒供電能力有關。目前沒有同步電壓、電流或溫升量測，不能據此定論為供電不穩，也不能排除接線、機構負載或馬達本體因素。

下一輪暫以三組彼此獨立的 `4 × AA` 電池盒驗證：原電池盒 A 只供位置型分類 MG996R；原電池盒 B 供三站 SG90 與分類器擋臂 SG90；新電池盒 C 只供送料 360° MG996R。三路正極完全隔離，三路負極與 ESP32 GND 共地。這是待量測驗證方案，不是已驗收的正式配置。

每盒都要記錄空載電壓、正常動作中的最低電壓、開關與配電端子溫升；另記錄送料馬達未起轉次數與 ESP32 reset。新 ESP32 接回前必須完全斷電，檢查極性、裸線、平台金屬件可能接觸處、USB 回灌路徑及共地，再依 A、B、C 逐盒送電。任何電擊感、電腦黑屏、異常溫升或 ESP32 reset 都立即斷電並停止驗收。

## 位置型 MG996R 分類機構

位置型 MG996R 位於三站流程之後，依人工分類結果轉向實體出口。它不參與前三站拍攝或 Gate 3 交握，且沒有位置回授。供電、共地與機械驗收見 [`hardware_notes/硬體接線與驗收摘要.md`](../hardware_notes/硬體接線與驗收摘要.md)。

實測需確認：

- 四個出口與 Home 都不碰硬限位。
- 外部電源壓降、溫升與 ESP32 是否重啟。
- 重複 command 或 report retry 不會再次轉動。
- 分類器錯誤復原不會驅動三站閘門。

## 維修與實機觀察

每次拆裝後檢查：

1. 不同尺寸、形狀與蒂頭方向的果實能否依序攔截與放行。
2. 相鄰 L 型桿完整旋轉時是否碰撞。
3. 第 2、3 站 ready 前果實是否已停止。
4. 感測器是否避開桿件，移位後是否仍穩定。
5. 馬達墊高件、ㄇ型鐵、連桿與底板是否鬆動。
6. 外部電源、共地與線材是否發熱或接觸不良。
7. 送料馬達停止時是否爬行，HC-SR04 觸發並停止前是否始終只送出一顆。
